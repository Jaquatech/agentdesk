# Decisions

One line per decision, with the reason, so nobody raises it again. Add to it at every gate (see `standards.md`).

## Settled

- **Chat history window is 16 messages (setting `chat_history_messages`, allowed 6–40).** Both chat paths used a hard-coded 20. One setting is the only number, and 16 keeps the current request while sending less text on every call. Storage: `chats.history_rolled_to` is the last message id already folded into the journal. That fold is one `project_journal` row, written once per window slide, not on every message. `runs.prompt_chars` is the character length of the system text plus the prompt, so the chat header can show a rough size of the last call (about 4 characters per token). That count is only the first prompt of a call, not later tool results, which is why the header calls the size rough.
- **No automatic formatter for now.** The code uses semicolons, double quotes and long lines, one component per file. A formatter would rewrite most files and bury real changes in diffs. Revisit as its own single "format everything" commit if the style starts to drift.
- **We do not use the UI SDK library.** Radix through shadcn already provides focus, keyboard, dismissal and ARIA. Revisit if a primitive we need is missing or wrong.
- **The isometric office is outside the shadcn system.** It is canvas drawing; its chrome CSS stays hardcoded at the bottom of `styles.css`.
- **Models, agents and tool output are untrusted.** They are shown as text or sanitized Markdown and never as raw HTML.
- **The server sends a strict CSP and related headers** (`server/src/securityHeaders.ts`). The UI loads only from its own origin, so images in Markdown that point to other sites are not shown. That is intended: it stops tracking pixels and data leaving through a model's output. The page has no inline scripts (the theme script is `web/public/theme-init.js`).
- **Chat drafts live in memory and `sessionStorage`, not `localStorage`.** The unsent text can be private. `sessionStorage` drops it when the tab closes; `localStorage` would leave it on disk. The stored value is the text plus attachment ids and names (the bytes stay on the server). Preview URLs stay in memory only, because they die on a refresh.
- **A chat attachment keeps its original bytes.** The Markdown copy is `data/attachments/<chat id>/<id>.md`, beside `<id>-<name>`. `attachments.status` is `converted`, `truncated`, `failed: reason`, `needs_ocr`, or empty. The original path is never overwritten. `read_attachment` takes a file name from that chat and a part number. It does not take a path, so a model cannot point it at another folder. Settings Clear and deleting the chat remove the copy with the original, because both live in the chat's folder.
- **Excel, Word and PDF copies use four pinned packages, and no others.** Measured outside the repo before install (installed size is the whole `node_modules` tree; downloads are npm's week of 16–22 Nov 2026). `read-excel-file` 9.3.20, MIT, 4,434,469 bytes, 5,720,267 downloads, released 2026-11-19, 4 direct and 2 transitive dependencies, `npm audit` 0. It is read-only and returns one row array per sheet. `mammoth` 1.13.0, BSD-2-Clause, 4,931,042 bytes, 16,967,369 downloads, released 2026-09-26, 8 direct and 15 transitive, audit 0. Its own Markdown writer is deprecated and drops tables, so HTML from mammoth goes through `node-html-markdown` 2.0.0, MIT, 1,480,756 bytes, 1,258,456 downloads, released 2025-11-14, 1 direct and 10 transitive, audit 0. `unpdf` 1.9.1, MIT, 2,174,290 bytes, 0 dependencies, audit 0, released 2026-10-19. The name has 13,054,972 weekly downloads, mostly of 2.x. `unpdf` 2.2.2 needs Node 24; this app is Node 22, so the pin stays on 1.9.1. `extractText` without `mergePages` is one string per page. Not chosen: `xlsx` 0.18.5 (14,043,448 bytes, audit 1 high for prototype pollution and ReDoS, published 2022-03-24; the fixed SheetJS build is not on npm), `word-to-markdown` 0.9.0 (48,635,732 bytes, 175 other packages, audit 3 high and 2 low), `pdfjs-dist` 6.5.438 (37,616,588 bytes, and a normal install also pulled optional `@napi-rs/canvas` for 73,646,803 bytes). A sheet keeps 200 rows and 20 columns (`SHEET_ROW_CAP`, `SHEET_COL_CAP`); anything past that sets `truncated` and the copy says how many rows and columns were left out. A PDF with no text on any page is `needs_ocr` and no copy is written.

- **Lint is a ratchet.** ESLint (typescript-eslint, react-hooks, jsx-a11y) runs with `--max-warnings` set to today's count, so existing issues are warnings and any new one fails CI. When you fix warnings, lower the number in the root `package.json` `lint` script. Generated shadcn files in `web/src/components/ui/` are not linted.

- **Dependency overrides in the root `package.json`.** ESLint is on 10; `eslint-plugin-jsx-a11y` only declares support for 9, so it is allowed through an override (it works; remove the override when the plugin adds 10). `minimatch` is forced to 11 only under `@typescript-eslint/typescript-estree` and `@ts-morph/common` to clear an advisory; a global override breaks the accessibility plugin, which needs the old one.
- **Accepted audit findings: 4 moderate, all one chain inside the `shadcn` command-line tool.** `shadcn` is a dev dependency, used only to add UI components, and is never part of the running app. The chain is `shadcn` > `ts-morph` > `@ts-morph/common` > a nested `minimatch` with a denial-of-service advisory (GHSA-g3hv-75wg-m249). No fix is available without a newer `shadcn`, because its `ts-morph` pins the old `@ts-morph/common`. `npm audit --omit=dev` reports 0, and CI fails if that changes (`npm audit --omit=dev --audit-level=moderate`). A full lockfile regeneration once dropped the TypeScript 7 platform package and broke the build, so the lockfile is only changed incrementally. Run `npm audit` before a release, and re-check when `shadcn` is updated.

- **Attachment limits are settings per file type.** The right size depends on the file: a wide spreadsheet needs more columns than a text file needs characters. The defaults equal the former constants, so nothing changes until the owner changes it. Changes apply to later uploads only, so earlier copies stay as the agent saw them.
- **Licences are checked against an allow-list from the lockfile.** `server/src/licenses.ts` allows only permissive and file-level licences. A GPL or AGPL package would change what the owner can distribute, so `licenses:check` in CI fails on it, on a missing licence, or on a stale `THIRD_PARTY_NOTICES.md`. The check reads `package-lock.json` and needs no dependency.
- **Zlib is on the licence allow-list.** It is a permissive licence (like MIT), and the package pako is licensed MIT AND Zlib. Approved by the owner's architect role when the licence check was added.

- **Token efficiency is a written rule (`standards.md`, one bullet in `CLAUDE.md`).** AgentDesk exists to show good, token-efficient ways to use AI, so every prompt change states its size and lookups use tools. The reason for writing it down: a principle that is only remembered gets undone without anyone noticing. No measurement was made for the rule itself; the measured cases are the chat window (above) and the attachment limits.
- **The README states the design choices, and is updated in the same change as any choice it names.** The "Design choices" section is what a new user reads first, so a choice that moves without it misleads them. `server/test/readmeDesign.test.ts` checks that the section exists and stays short; it does not check its wording.
- **PDF pages are rendered with `@hyzyla/pdfium`.** MIT, one package without dependencies, about 14 MB, no audit findings, Node 22 supported; it renders a page in a few milliseconds. Chosen over `mupdf` (AGPL), `@napi-rs/canvas` (73 MB) and `tesseract.js` (large core and language downloads). Approved by the owner.

## Known and open

- Lint has no warnings left and the cap in `package.json` is 0, so a new warning fails CI. `any` is allowed in test files only (parsed JSON and loose fixtures). In `src` three places keep `any` on purpose, each with a comment saying why: the database rows (`db.ts`), request bodies (`Body` in routes, teams and Scrum) and the tool input from the model (`runTool`). Hook rules: effects keyed on a computed string or a caller's list carry a comment saying why.
- `npm audit` (Gate 3 after v1.4.0) found 4 moderate and 2 low issues, all inside the `shadcn` package (an old `deepmerge`, and `minimatch` under `ts-morph`). `shadcn` is now a devDependency: the build imports one CSS file from it and the command line adds components, nothing of it runs in the app or the server, and `npm audit --omit=dev` reports 0. The dev-only findings remain until shadcn publishes a fix (`npm audit fix --force` would install shadcn 1.0.0, a breaking change). The root `overrides` for `minimatch` does not match what `ts-morph` installs (`npm ls` marks it invalid); harmless, tidy it with the next dependency update.

- Reading scans: the setting exists, the renderer and reading pipeline are not built; a renderer dependency needs the owner's approval.
- `pages/scrum/Sprints.tsx` is about 280 lines and holds four views (PI, sprint, task, plan); split it if it grows.
- Browser checks (`e2e/`, Playwright, run by CI) cover page loads, the seeded data, one keyboard flow, the sprint flow end to end (approval, merge, release) and an automated accessibility scan (axe, WCAG 2.0/2.1 A and AA) of every page in both themes. The scan sees only a part of the problems. Besides every page it opens nine states (project, agent, provider, team and backlog-item dialogs, the agent gallery, a task needing attention, the chat). Not scanned yet: forms showing validation errors, open dropdowns and the approval banner. Still to add: those, and more flows (approvals, Merge, release).
- The accessibility scan skips the tab buttons (`[role="tab"]`): Radix points them at panels (`aria-controls`) that these pages do not render, since the tabs only switch what the page shows below. Fix by rendering a panel per tab, or by dropping the attribute.
- The CSP allows inline styles (`style-src 'unsafe-inline'`) because Radix injects style elements. Tighten with a nonce if that changes.
- With reduced motion the office is a still picture: agents do not walk to a new place when their state changes until the page is reloaded (labels and bubbles still update).
